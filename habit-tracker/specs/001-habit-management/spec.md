# Feature Specification: 習慣管理（CRUD・カテゴリ分類）

**Feature Branch**: `001-habit-management`

**Created**: 2026-08-07

**Status**: Draft

**Input**: User description: "習慣の登録・編集・削除・一覧表示ができ、習慣ごとに頻度（毎日/毎週など）を設定できる。また習慣をカテゴリ（健康・仕事・学習など）で分類し、カテゴリ別に一覧・絞り込みができる。チェックインやストリーク計算は対象外（002で扱う）。"

## Clarifications

### Session 2026-08-07

- Q: 習慣に「アーカイブ（一時停止）」状態を持たせるか、それとも削除のみで良いか？ →
  A: 削除のみとする。アーカイブ（一時停止）状態は追加しない。

## User Scenarios & Testing *(mandatory)*

本機能はテスト駆動で実装する。各ユーザーストーリーの実装前にテストを作成し、失敗することを
確認したうえで実装を行う。

### User Story 1 - 習慣を登録する (Priority: P1)

ユーザーは、続けたい新しい習慣を名前・頻度・カテゴリを指定して登録できる。

**Why this priority**: 習慣を登録できなければアプリの他のすべての機能（一覧・編集・削除・
将来のチェックイン）が成立しないため、最初に実現すべきMVPの中核。

**Independent Test**: 習慣登録フォームから名前・頻度・カテゴリを入力して登録操作を行い、
一覧に登録した習慣が表示されることを確認するだけで、単独で価値を検証できる。

**Acceptance Scenarios**:

1. **Given** 習慣が1件も登録されていない状態、**When** ユーザーが名前「読書」・頻度「毎日」・
   カテゴリ「学習」を入力して登録する、**Then** 習慣一覧に「読書」が表示される。
2. **Given** 習慣登録フォームが表示されている状態、**When** ユーザーが名前を入力せずに登録を
   実行する、**Then** システムは名前が必須である旨のエラーを表示し、登録を行わない。
3. **Given** 習慣登録フォームが表示されている状態、**When** ユーザーが頻度・カテゴリを指定
   せずに名前のみ入力して登録する、**Then** 頻度は「毎日」、カテゴリは「未分類」として
   登録される。

---

### User Story 2 - 習慣の一覧を確認し編集・削除する (Priority: P2)

ユーザーは、登録済みの習慣を一覧で確認し、内容を編集したり不要になった習慣を削除できる。

**Why this priority**: 登録した習慣を継続的に管理（見直し・整理）できることは、日々の
運用において登録に次いで重要な操作。

**Independent Test**: 事前に登録済みの習慣を1件用意し、一覧から編集して内容が更新される
こと、削除して一覧から消えることを確認するだけで、単独で価値を検証できる。

**Acceptance Scenarios**:

1. **Given** 習慣「読書」が登録されている状態、**When** ユーザーが一覧を開く、**Then**
   「読書」が名前・頻度・カテゴリとともに表示される。
2. **Given** 習慣「読書」が登録されている状態、**When** ユーザーが頻度を「毎週（月・水・
   金）」に変更して保存する、**Then** 一覧に変更後の頻度が反映される。
3. **Given** 習慣「読書」が登録されている状態、**When** ユーザーが削除を実行し確認ダイアログ
   で削除を確定する、**Then** 「読書」は一覧から消える。
4. **Given** 削除確認ダイアログが表示されている状態、**When** ユーザーが削除をキャンセル
   する、**Then** 習慣は削除されず一覧に残る。
5. **Given** 存在しない習慣IDに対して編集・削除を実行した、**When** リクエストが処理される、
   **Then** システムはエラーを返し、他の習慣データに影響を与えない。

---

### User Story 3 - カテゴリで習慣を分類・絞り込む (Priority: P3)

ユーザーは、習慣をカテゴリ（健康・仕事・学習・その他）で分類し、特定のカテゴリの習慣だけを
一覧に絞り込んで表示できる。

**Why this priority**: 登録する習慣が増えるほど一覧が見づらくなるため、分類・絞り込みは
運用効率を高める機能だが、登録・編集・削除が成立していなくても単独で価値を持つ範囲は限定的
であるため優先度は最も低い。

**Independent Test**: 異なるカテゴリの習慣を複数件登録した状態で、カテゴリを1つ選択して
一覧を絞り込み、選択したカテゴリの習慣のみが表示されることを確認するだけで、単独で価値を
検証できる。

**Acceptance Scenarios**:

1. **Given** カテゴリ「健康」の習慣2件と「学習」の習慣1件が登録されている状態、**When**
   ユーザーがカテゴリ「健康」で絞り込む、**Then** 「健康」の習慣2件のみが一覧に表示される。
2. **Given** カテゴリによる絞り込みが適用されている状態、**When** ユーザーが絞り込みを
   解除する、**Then** すべての習慣が再び一覧に表示される。

---

### Edge Cases

- 同じ名前の習慣を複数回登録した場合はどうなるか？ → 名前の重複はエラーとせず許可する
  （各習慣は内部的に一意のIDで区別される）。
- 頻度で「毎週」を選択したが曜日を1つも指定しなかった場合はどうなるか？ → システムは
  最低1つの曜日指定を必須とし、未指定の場合はエラーを表示する。
- カテゴリ「未分類」の習慣を絞り込みで選択できるか？ → できる。「未分類」も他のカテゴリと
  同様に選択可能な絞り込み対象として扱う。
- 習慣が0件の状態で一覧やカテゴリ絞り込みを開いた場合はどうなるか？ → 「登録されている
  習慣がありません」というメッセージを表示する。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、ユーザーが名前・頻度・カテゴリ（任意）を指定して新しい習慣を
  登録できなければならない。
- **FR-002**: システムは、習慣の名前を1文字以上100文字以下の必須項目として検証しなければ
  ならない。
- **FR-003**: システムは、頻度として「毎日」または「毎週（曜日を1つ以上指定）」を選択
  できなければならない。
- **FR-004**: システムは、頻度が指定されない場合、デフォルトで「毎日」を設定しなければ
  ならない。
- **FR-005**: システムは、頻度に「毎週」が選択され曜日が1つも指定されない場合、エラーを
  返さなければならない。
- **FR-006**: システムは、習慣にカテゴリ（健康・仕事・学習・その他）を1つ設定できなければ
  ならない。カテゴリが指定されない場合は「未分類」として扱う。
- **FR-007**: システムは、登録済みの全習慣を一覧表示できなければならない。
- **FR-008**: システムは、習慣一覧をカテゴリ（未分類を含む）で絞り込み表示できなければ
  ならない。
- **FR-009**: システムは、既存の習慣の名前・頻度・カテゴリを編集できなければならない。
- **FR-010**: システムは、既存の習慣を削除できなければならない。
- **FR-011**: システムは、削除実行前にユーザーへ確認を求め、確認が得られるまで削除を
  実行してはならない。
- **FR-012**: システムは、存在しない習慣IDに対する編集・削除操作に対してエラーを返し、
  他の習慣データに影響を与えてはならない。

### Key Entities

- **習慣（Habit）**: ユーザーが継続したい行動を表す。名前、頻度（毎日/毎週+曜日）、
  カテゴリ、作成日時、更新日時を持つ。
- **カテゴリ（Category）**: 習慣を分類するための固定ラベル。「健康」「仕事」「学習」
  「その他」「未分類」のいずれかの値を取る。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ユーザーは新しい習慣を1分以内に登録できる。
- **SC-002**: ユーザーは登録済み習慣の一覧を3秒以内に確認できる。
- **SC-003**: ユーザーはカテゴリによる絞り込みを2操作以内で行える。
- **SC-004**: 習慣の削除操作は100%確認ステップを経て実行され、確認なしの削除は発生しない。
- **SC-005**: 必須項目（名前、毎週選択時の曜日）が欠落した登録・編集操作は100%エラーとして
  検出される。

## Assumptions

- カテゴリは「健康」「仕事」「学習」「その他」「未分類」の固定リストとし、ユーザーによる
  カテゴリの新規作成・編集は本フェーズのスコープ外とする。
- 頻度の選択肢は「毎日」「毎週（曜日指定）」の2種類とし、「毎月」など、より複雑な頻度
  パターンは本フェーズのスコープ外とする。
- 本機能は単一ユーザー利用を前提とし、ユーザー認証・複数ユーザー対応は本フェーズの
  スコープ外とする。
- チェックイン記録・ストリーク計算は `002-checkin-tracking` で扱うため、本フェーズでは
  習慣の登録・編集・削除・一覧・カテゴリ分類のみを対象とする。
- 削除は物理削除とし、確認後は元に戻せない。アーカイブ（一時停止）などの中間状態は本機能
  では持たない（[Clarifications](#clarifications)参照）。
