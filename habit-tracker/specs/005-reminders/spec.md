# Feature Specification: リマインダー

**Created**: 2026-09-06

**Status**: Draft

## User Scenarios & Testing *(mandatory)*

本機能はテスト駆動で実装する。各ユーザーストーリーのAPI・ドメインロジック実装前にテストを
作成し、失敗することを確認したうえで実装を行う。フロントエンドUI（`public/`配下のVanilla
JS）はDOMテストツールを導入していないため自動テスト対象外とし、`quickstart.md`による手動
検証で品質を保証する。

### User Story 1 - 今日まだ実行していない習慣に気づく (Priority: P1)

ユーザーは、アプリを開いた際に、今日まだ実行していない（チェックインしていない）習慣の
一覧をひと目で確認できる。

**Why this priority**: 習慣を忘れずに実行するための最も基本的な仕組みであり、この機能
なしにはリマインダーとしての価値が成立しないため、最初に実現すべき中核機能。

**Independent Test**: 頻度「毎日」の習慣を2件登録し、1件だけ本日チェックインした状態で
アプリを開き、未チェックインの1件だけがリマインダー一覧に表示されることを確認するだけ
で、単独で価値を検証できる。

**Acceptance Scenarios**:

1. **Given** 頻度「毎日」の習慣「読書」が本日まだチェックインされていない状態、
   **When** ユーザーがアプリを開く、**Then** 「読書」がリマインダー一覧に表示される。
2. **Given** 頻度「毎日」の習慣「読書」が本日既にチェックインされている状態、
   **When** ユーザーがアプリを開く、**Then** 「読書」はリマインダー一覧に表示されない。
3. **Given** 頻度「毎週（月・水・金）」の習慣が、本日は対象外の曜日（例: 火曜）である
   状態、**When** ユーザーがアプリを開く、**Then** その習慣はリマインダー一覧に
   表示されない。
4. **Given** 今日が対象日の習慣がすべてチェックイン済み、かつ他に対象習慣がない状態、
   **When** ユーザーがアプリを開く、**Then** 「今日の習慣はすべて実行済みです」旨の
   メッセージが表示される。

---

### User Story 2 - リマインダーからその場でチェックインする (Priority: P2)

ユーザーは、リマインダー一覧に表示された習慣を、一覧を離れることなくその場で
チェックインできる。

**Why this priority**: リマインダーで未実行に気づけても（User Story 1）、チェックイン
操作のために習慣一覧まで移動する必要があると手間が増え、リマインダーの効果が薄れる
ため、優先度2として追加する。

**Independent Test**: リマインダー一覧に表示されている習慣のチェックインボタンを押し、
その習慣がリマインダー一覧から消え、習慣一覧側にも本日チェックイン済みとして反映
されることを確認するだけで、単独で価値を検証できる。

**Acceptance Scenarios**:

1. **Given** 習慣「読書」がリマインダー一覧に表示されている状態、**When** ユーザーが
   リマインダー一覧内のチェックインボタンを押す、**Then** 「読書」はリマインダー
   一覧から消え、本日チェックイン済みとして記録される。
2. **Given** 習慣「読書」が既に本日チェックイン済みで重複してチェックインしようとした
   （例: 二重クリック）、**When** リクエストが処理される、**Then** システムはエラーを
   返し、重複して記録しない（`002-checkin-tracking`のFR-005を踏襲）。

---

### User Story 3 - 特定の習慣をリマインダー対象から除外する (Priority: P3)

ユーザーは、習慣ごとにリマインダー一覧への表示有無を設定できる。

**Why this priority**: すべての習慣についてリマインダーを表示すると、重要度の低い習慣
まで一覧に並び、本当に忘れたくない習慣が埋もれる可能性がある。この調整はUser Story
1・2が成立していれば独立して後から追加できる機能のため優先度3とする。

**Independent Test**: 習慣「ストレッチ」のリマインダー表示を無効に設定し、本日未実行
であってもリマインダー一覧に表示されないことを確認するだけで、単独で価値を検証できる。

**Acceptance Scenarios**:

1. **Given** 習慣「ストレッチ」が本日未実行かつリマインダー表示が有効な状態、
   **When** ユーザーがリマインダー表示を無効に設定する、**Then** 「ストレッチ」は
   以降リマインダー一覧に表示されなくなる。
2. **Given** 習慣「ストレッチ」のリマインダー表示が無効な状態、**When** ユーザーが
   再度有効に設定する、**Then** 本日未実行であれば「ストレッチ」がリマインダー
   一覧に再び表示される。
3. **Given** 新規に習慣を登録した直後の状態、**When** ユーザーがリマインダー一覧を
   確認する、**Then** その習慣はデフォルトでリマインダー表示が有効な状態として
   扱われる。

---

### Edge Cases

- 習慣が1件も登録されていない場合はどうなるか？ → リマインダー一覧は空となり、
  「今日の習慣はすべて実行済みです」等のメッセージが表示される（登録なし・全実行
  済みを区別しないシンプルな表示とする）。
- リマインダー表示を無効にした習慣が削除された場合はどうなるか？ → 習慣の削除
  （物理削除）に伴い、リマインダー表示設定も併せて削除される（他機能同様の方針）。
- 習慣の頻度が「毎週」から「毎日」に変更された場合、リマインダー対象の判定はどう
  なるか？ → 常に習慣の現在の頻度設定を基準に、その日が対象日かどうかを都度判定
  する（`002-checkin-tracking`のストリーク再計算方針を踏襲）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、本日が対象日（頻度「毎日」は常に対象、頻度「毎週」は
  指定曜日のみ対象）でありながら未チェックインの習慣を、リマインダー一覧として
  取得できなければならない。
- **FR-002**: システムは、本日が対象日でない習慣を、リマインダー一覧に含めては
  ならない。
- **FR-003**: システムは、本日既にチェックイン済みの習慣を、リマインダー一覧に
  含めてはならない。
- **FR-004**: ユーザーは、リマインダー一覧に表示された習慣に対し、一覧の操作画面を
  離れることなくチェックインを実行できなければならない。
- **FR-005**: システムは、リマインダー経由のチェックインについても、既存のチェック
  イン検証（重複防止・未来日禁止・作成日より前禁止）をすべて適用しなければ
  ならない。
- **FR-006**: ユーザーは、習慣ごとにリマインダー一覧への表示有無（有効/無効）を
  設定できなければならない。
- **FR-007**: システムは、リマインダー表示設定が指定されていない習慣を、デフォルトで
  「有効」として扱わなければならない。
- **FR-008**: システムは、リマインダー対象の習慣が1件もない場合、エラーを発生させる
  ことなく「今日の習慣はすべて実行済みです」旨のメッセージを表示できる状態を返さ
  なければならない。
- **FR-009**: システムは、習慣が削除された場合、その習慣に紐づくリマインダー表示
  設定も併せて削除しなければならない。

### Key Entities

- **リマインダー一覧（ReminderList）**: 永続化されるエンティティではなく、習慣・
  チェックイン・リマインダー表示設定から都度計算される導出値。「本日が対象日かつ
  未チェックインかつリマインダー表示が有効」な習慣の集合を表す。
- **リマインダー表示設定（ReminderPreference）**: 習慣（Habit）に対して1件のみ
  存在する設定。有効/無効（真偽値）を保持する。習慣の新規登録時に暗黙的に
  「有効」が適用され、明示的に設定を変更するまでその状態が維持される。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ユーザーはアプリを開いた1回の操作で、本日未実行の対象習慣をすべて
  確認できる。
- **SC-002**: リマインダー一覧の表示内容は、対象日・チェックイン状況・リマインダー
  表示設定から100%正しく算出される（対象外の習慣・チェックイン済みの習慣・表示
  無効の習慣が0件のケースで混入する）。
- **SC-003**: リマインダー一覧からのチェックインは1回の操作で完了し、3秒以内に
  一覧から該当習慣が消える。
- **SC-004**: リマインダー対象が0件の場合、100%のケースでエラーにならず「すべて
  実行済み」の表示になる。

## Assumptions

- リマインダーは、ユーザーがアプリを開いた（ページを読み込んだ）タイミングで
  アプリ内に表示する方式とする。ブラウザの通知機能（Web Notification API等）や
  メール・プッシュ通知など、アプリを開いていない状態でユーザーに能動的に通知を
  送る仕組みは本フェーズのスコープ外とする。本プロジェクトはローカル環境で
  `npm run dev`実行時のみサーバーが稼働する構成（`001`〜`004`と同様）であり、
  アプリが開かれていない間に時刻を基準とした通知を送るには常駐サーバーや外部
  通知サービスとの連携が必要になり、個人利用規模を超えた過剰な仕組みとなるため
  （憲章原則V、シンプルさ）。
- 特定の時刻（例: 毎日20時）に基づくリマインダーは本フェーズのスコープ外とする。
  リマインダーは常に「アプリを開いた時点の日付」を基準に算出する。
- リマインダー表示設定（有効/無効）は習慣単位のシンプルな真偽値とし、時間帯・
  曜日ごとの詳細な通知条件などは本フェーズのスコープ外とする。
- 日付・「今日」の判定は`002-checkin-tracking`で確定した日本時間（JST, UTC+9）
  固定方式を踏襲する。
- リマインダー一覧からのチェックイン（User Story 2）は、`002-checkin-tracking`で
  確立したチェックイン検証ロジックをそのまま再利用し、新しい検証ルールは追加
  しない。
