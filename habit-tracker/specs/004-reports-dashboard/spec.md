# Feature Specification: レポート・ダッシュボード

**Feature Branch**: `004-reports-dashboard`

**Created**: 2026-09-04

**Status**: Draft

**Input**: User description: "004-reports-dashboard"

## Clarifications

### Session 2026-09-04

- Q: カテゴリ別達成率（FR-006, User Story 2）は、今週・今月のどちらを対象に集計するか？
  → A: 今週・今月の両方をそれぞれ集計して表示する（習慣ごとの達成率と同様、短期・長期
  両方の傾向を比較できるようにする）。

## User Scenarios & Testing *(mandatory)*

本機能はテスト駆動で実装する。各ユーザーストーリーのAPI・ドメインロジック実装前にテストを
作成し、失敗することを確認したうえで実装を行う。フロントエンドUI（`public/`配下のVanilla
JS）はDOMテストツールを導入していないため自動テスト対象外とし、`quickstart.md`による手動
検証で品質を保証する。

### User Story 1 - 習慣ごとの実行状況ダッシュボードを見る (Priority: P1)

ユーザーは、習慣一覧とは別に、各習慣の直近の実行状況（今週・今月の達成率、これまでの
最長ストリーク）をまとめて確認できる。

**Why this priority**: 習慣一覧画面では現在のストリークしか分からず、継続の全体像や
過去の最長記録を振り返る手段がないため、最初に実現すべき中核機能。

**Independent Test**: 複数日チェックインした習慣についてダッシュボードを開き、今週の
達成率と最長ストリークが正しく表示されることを確認するだけで、単独で価値を検証できる。

**Acceptance Scenarios**:

1. **Given** 頻度「毎日」の習慣が直近7日間のうち5日チェックインされている状態、
   **When** ユーザーがダッシュボードを開く、**Then** その習慣の「今週の達成率」は
   対象日数に対する実施日数の割合（例: 5/7）として表示される。
2. **Given** 習慣が過去に7日間の連続記録を達成し、その後途切れて現在のストリークが
   2日である状態、**When** ユーザーがダッシュボードを開く、**Then** 「最長ストリーク」
   は7日、「現在のストリーク」は2日として、両方が表示される。
3. **Given** 習慣がまだ一度もチェックインされていない状態、**When** ユーザーが
   ダッシュボードを開く、**Then** 達成率は0%、最長ストリークは0日と表示される。

---

### User Story 2 - カテゴリ別の達成状況を比較する (Priority: P2)

ユーザーは、習慣のカテゴリ（健康・仕事・学習・その他・未分類）ごとに、今週・今月それぞれの
達成率を集計して比較できる。

**Why this priority**: カテゴリ単位でどの分野が続けられていて、どの分野がおろそかに
なっているかを把握できる点は`001-habit-management`のカテゴリ分類機能の価値を活かすが、
個々の習慣の状況（User Story 1）が先に確認できることが前提となるため優先度2。

**Independent Test**: 異なるカテゴリの習慣を複数登録し、一部にのみチェックインした状態で
ダッシュボードを開き、カテゴリごとの達成率が習慣単位の実績から正しく集計されていることを
確認するだけで、単独で価値を検証できる。

**Acceptance Scenarios**:

1. **Given** カテゴリ「健康」に2件、カテゴリ「学習」に1件の習慣が登録され、今週の対象日に
   それぞれ一部チェックインされている状態、**When** ユーザーがダッシュボードを開く、
   **Then** カテゴリごとに、そのカテゴリに属する習慣の実施日数合計・対象日数合計から
   算出した「今週の達成率」が表示される。
2. **Given** 上記と同じ状態で今月の対象日についても一部チェックインされている状態、
   **When** ユーザーがダッシュボードを開く、**Then** カテゴリごとに「今月の達成率」も
   同様に算出され、今週の達成率と併記される。
3. **Given** あるカテゴリに習慣が1件も登録されていない状態、**When** ユーザーが
   ダッシュボードを開く、**Then** そのカテゴリは今週・今月いずれの集計結果からも
   除外される。

---

### User Story 3 - 目標の達成状況を一覧で振り返る (Priority: P3)

ユーザーは、これまでに設定したすべての目標について、達成済み・未達成・進行中の状況を
一覧で確認できる。

**Why this priority**: 個々の目標は`003-goal-management`の目標一覧画面でも確認できるが、
期間が終了した目標も含めた振り返り用の一覧はまだないため、優先度3として追加する。

**Independent Test**: 達成済みの目標と未達成の目標を1件ずつ用意し、ダッシュボードの
目標振り返り一覧を開いて、それぞれが正しい状態（達成/未達成）で表示されることを確認する
だけで、単独で価値を検証できる。

**Acceptance Scenarios**:

1. **Given** 期間が終了し達成条件を満たした目標が1件、達成条件を満たさなかった目標が
   1件存在する状態、**When** ユーザーがダッシュボードの目標振り返り一覧を開く、**Then**
   前者は「達成」、後者は「未達成」として表示される。
2. **Given** 期間内でまだ終了していない目標が存在する状態、**When** ユーザーが
   ダッシュボードを開く、**Then** その目標は「進行中」として表示され、現在の進捗率も
   併記される。

---

### Edge Cases

- チェックインが1件もない習慣のみが登録されている場合はどうなるか？ → すべての集計値は
  0（達成率0%、最長ストリーク0日）として表示され、エラーにはならない。
- 習慣・チェックイン・目標のいずれも登録されていない場合はどうなるか？ → 「表示できる
  データがありません」旨のメッセージを表示する。
- 集計対象期間（今週・今月）の途中で習慣が新規登録された場合、対象日数はどう数えるか？ →
  習慣の作成日以降の対象日のみを集計対象に含める（作成前は対象日数に含めない）。
- 頻度「毎週」の習慣で対象曜日以外の日はどう扱われるか？ → 対象日数・実施日数の
  いずれにもカウントしない（`002-checkin-tracking`のストリーク計算と同様の扱い）。
- 目標が削除された場合、振り返り一覧の表示はどうなるか？ → 削除された目標は一覧から
  消える（他機能同様、物理削除方針を踏襲する）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、習慣ごとに直近7日間（今週）の達成率（対象日数に対する実施日数の
  割合）を算出できなければならない。
- **FR-002**: システムは、習慣ごとに直近30日間（今月）の達成率を算出できなければならない。
- **FR-003**: システムは、習慣ごとにこれまでの最長ストリーク（連続実施日数の最大値）を
  算出できなければならない。
- **FR-004**: 最長ストリークの算出は、習慣の頻度（毎日/毎週+曜日）に応じて対象日のみを
  考慮し、現在のストリーク計算（`002-checkin-tracking`）と同じ対象日判定ロジックを
  使用しなければならない。
- **FR-005**: システムは、頻度が変更された場合も、既存のチェックイン履歴を含め常に
  現在の頻度設定を基準に最長ストリーク・達成率を再計算しなければならない（現在の
  ストリーク計算と同じ方針）。
- **FR-006**: システムは、カテゴリ（健康/仕事/学習/その他/未分類）ごとに、そのカテゴリに
  属する全習慣の実施日数合計・対象日数合計から算出した達成率を、今週・今月それぞれの
  期間で集計できなければならない（[Clarifications](#clarifications)参照）。
- **FR-007**: システムは、習慣が1件も属さないカテゴリを集計結果から除外しなければ
  ならない。
- **FR-008**: システムは、すべての目標について、期間終了の有無と達成条件の充足有無に
  基づき「進行中」「達成」「未達成」のいずれかの状態を判定できなければならない。
- **FR-009**: システムは、「進行中」の目標について、現在の進捗率（`003-goal-management`で
  定義された算出方法）を併記しなければならない。
- **FR-010**: システムは、習慣の作成日より前の日付を、達成率・最長ストリークいずれの
  対象日数にも含めてはならない。
- **FR-011**: システムは、習慣・チェックイン・目標のいずれも登録されていない場合、
  エラーを発生させることなく「表示できるデータがありません」旨のメッセージを表示できる
  状態を返さなければならない。
- **FR-012**: システムは、ダッシュボードの集計結果を永続化せず、習慣・チェックイン・
  目標の既存データから都度算出しなければならない。

### Key Entities

- **週次達成率（WeeklyCompletionRate）**: 習慣ごとに算出される導出値。直近7日間の
  対象日数と実施日数から算出する。永続化しない。
- **月次達成率（MonthlyCompletionRate）**: 週次達成率と同様の算出方法で、直近30日間を
  対象とする導出値。
- **最長ストリーク（LongestStreak）**: 習慣とそのチェックイン履歴全体から算出される
  導出値。現在のストリーク（`002-checkin-tracking`）とは独立した値として算出・表示するが、
  永続化はしない。
- **カテゴリ別達成率（CategoryCompletionRate）**: 同一カテゴリに属する複数の習慣の
  実施日数・対象日数を合算して算出する導出値。今週・今月それぞれの期間について算出する。
- **目標振り返り状態（GoalReviewStatus）**: 既存の目標（Goal, `003-goal-management`）に
  対して、期間終了・達成条件充足の判定結果として付与される「進行中/達成/未達成」の状態。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ユーザーは1回の画面遷移で、すべての習慣の今週・今月の達成率と最長
  ストリークを確認できる。
- **SC-002**: ダッシュボードを開いてから3秒以内に集計結果が表示される。
- **SC-003**: 対象日数が0件（チェックイン・習慣が存在しない等）の場合でも、100%の
  ケースでエラーにならず0%または「データなし」の表示になる。
- **SC-004**: カテゴリ別達成率は、そのカテゴリに属する習慣の実績から手計算した値と
  100%一致する。
- **SC-005**: 目標の状態判定（進行中/達成/未達成）は、期間終了日と達成条件から100%
  正しく分類される。

## Assumptions

- 「今週」は本日を含む直近7日間、「今月」は本日を含む直近30日間の固定日数ウィンドウと
  する。暦月・暦週（月曜始まり等）への対応は本フェーズのスコープ外とする。
- 日付・「今日」の判定は`002-checkin-tracking`で確定した日本時間（JST, UTC+9）固定方式を
  踏襲する。
- ダッシュボードは新規の永続化エンティティを持たず、既存の習慣・チェックイン・目標
  データからの導出値のみで構成する（他機能と同様、シンプルさを優先する）。
- 目標の「達成」判定は、目標の終了日（endDate）が本日以前であり、かつ
  `003-goal-management`で定義された達成条件（実施回数が目標回数以上）を満たす場合とする。
  終了日が本日より後の場合は「進行中」として扱う。
- グラフ・チャートによる視覚的表現の要否は本仕様では規定しない。数値・一覧表示で要件を
  満たすものとし、表示形式の詳細はUI実装時の判断に委ねる。
- カスタム期間指定（任意の開始日・終了日を選べる機能）は本フェーズのスコープ外とし、
  固定の今週・今月・カテゴリ別集計のみを対象とする。
