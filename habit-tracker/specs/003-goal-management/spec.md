# Feature Specification: 目標設定・進捗計算

**Feature Branch**: `003-goal-management`

**Created**: 2026-08-23

**Status**: Draft

**Input**: User description: "003-goal-management"

## User Scenarios & Testing *(mandatory)*

本機能はテスト駆動で実装する。各ユーザーストーリーのAPI・ドメインロジック実装前にテストを
作成し、失敗することを確認したうえで実装を行う。フロントエンドUI（`public/`配下のVanilla
JS）はDOMテストツールを導入していないため自動テスト対象外とし、`quickstart.md`による手動
検証で品質を保証する。

### User Story 1 - 目標を設定する (Priority: P1)

ユーザーは、習慣に対して期間（開始日・終了日）と目標回数を指定して目標を設定できる。

**Why this priority**: 目標を設定できなければ進捗確認・編集・削除は成立しないため、
最初に実現すべきMVPの中核。

**Independent Test**: 習慣に対して開始日・終了日・目標回数を指定して目標を設定し、
目標一覧に登録した目標が表示されることを確認するだけで、単独で価値を検証できる。

**Acceptance Scenarios**:

1. **Given** 習慣「読書」が登録されている状態、**When** ユーザーが開始日・終了日・
   目標回数（例: 今月1日〜末日、20回）を指定して目標を設定する、**Then** 目標一覧に
   登録した目標が表示される。
2. **Given** 目標設定フォームが表示されている状態、**When** ユーザーが終了日より後の
   日付を開始日として指定して設定する、**Then** システムはエラーを表示し、登録しない。
3. **Given** 目標設定フォームが表示されている状態、**When** ユーザーが目標回数を
   0以下の値で指定して設定する、**Then** システムはエラーを表示し、登録しない。

---

### User Story 2 - 目標の進捗を確認する (Priority: P2)

ユーザーは、設定した目標について、対象期間内の実績チェックイン数に基づく進捗率を
確認できる。

**Why this priority**: 目標を設定するモチベーションの核となる機能だが、目標設定
（User Story 1）が先に成立している必要があるため優先度2。

**Independent Test**: 目標回数10回の目標に対して期間内で5回チェックインされている
状態を用意し、目標一覧を開いて進捗率50%と表示されることを確認するだけで、単独で
価値を検証できる。

**Acceptance Scenarios**:

1. **Given** 目標回数10回の目標に対して対象期間内で5回チェックインが記録されている
   状態、**When** ユーザーが目標一覧を開く、**Then** 進捗率50%と表示される。
2. **Given** 目標回数以上のチェックインが対象期間内で記録されている状態、**When**
   ユーザーが目標一覧を開く、**Then** 進捗率100%・達成として表示される。
3. **Given** 対象期間内のチェックインが1件も記録されていない状態、**When** ユーザーが
   目標一覧を開く、**Then** 進捗率0%と表示される。

---

### User Story 3 - 目標を編集・削除する (Priority: P3)

ユーザーは、登録済みの目標の期間・目標回数を編集したり、不要になった目標を削除できる。

**Why this priority**: 目標設定後の見直し・整理に有用だが、設定と進捗確認（User
Story 1・2）が成立していれば独立して後から追加できる機能のため優先度3。

**Independent Test**: 登録済みの目標の目標回数を変更して保存し、進捗率が新しい目標
回数を基準に再計算されることを確認する。削除して一覧から消えることを確認するだけで、
単独で価値を検証できる。

**Acceptance Scenarios**:

1. **Given** 目標が登録されている状態、**When** ユーザーが目標回数を変更して保存する、
   **Then** 進捗率が新しい目標回数を基準に再計算されて表示される。
2. **Given** 目標が登録されている状態、**When** ユーザーが削除を実行し確認ダイアログで
   削除を確定する、**Then** その目標は一覧から消える。
3. **Given** 削除確認ダイアログが表示されている状態、**When** ユーザーが削除をキャンセル
   する、**Then** 目標は削除されず一覧に残る。
4. **Given** 存在しない目標IDに対して編集・削除を実行した、**When** リクエストが処理
   される、**Then** システムはエラーを返し、他のデータに影響を与えない。

---

### Edge Cases

- 開始日が終了日より後の場合はどうなるか？ → エラーを返し、登録・更新しない
  （Acceptance Scenario 1-2）。
- 目標回数が0以下または整数でない場合はどうなるか？ → エラーを返し、登録・更新
  しない（Acceptance Scenario 1-3）。
- 目標の開始日が対象習慣の作成日より前の場合はどうなるか？ → エラーを返し、登録
  しない。
- 目標回数を超えてチェックインした場合、進捗率はどう表示されるか？ → 100%として
  表示する（超過分は記録・表示しない）。
- 同一習慣に対して期間が重複する複数の目標を設定した場合はどうなるか？ → 許可し、
  それぞれ独立して進捗を計算する。
- 目標期間中に紐づくチェックインが取り消された場合はどうなるか？ → 進捗は都度
  計算される導出値のため、取り消し後の実績を反映して自動的に更新される。
- 習慣が削除された場合、紐づく目標はどうなるか？ → 習慣の削除（物理削除）に伴い、
  紐づく目標も削除される。
- 登録済みの目標が0件の場合はどうなるか？ → 「登録されている目標がありません」
  というメッセージを表示する。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、ユーザーが習慣に対して開始日・終了日・目標回数を指定して
  目標を設定できなければならない。
- **FR-002**: システムは、開始日が終了日より後の場合、エラーを返さなければならない。
- **FR-003**: システムは、目標回数を1以上の整数として検証し、0以下または非整数の
  場合はエラーを返さなければならない。
- **FR-004**: システムは、存在しない習慣IDに対する目標設定にエラーを返さなければ
  ならない。
- **FR-005**: システムは、目標の開始日が対象習慣の作成日より前の場合、エラーを
  返さなければならない。
- **FR-006**: システムは、各目標について、対象期間内の実際のチェックイン数から
  進捗率（実績チェックイン数 ÷ 目標回数）を計算できなければならない。
- **FR-007**: システムは、進捗率が100%を超える場合、表示上100%として扱わなければ
  ならない。
- **FR-008**: システムは、進捗率が100%に達した目標を「達成」として扱わなければ
  ならない。
- **FR-009**: システムは、登録済みの目標を一覧表示できなければならない。
- **FR-010**: システムは、既存の目標の開始日・終了日・目標回数を編集できなければ
  ならない。
- **FR-011**: システムは、既存の目標を削除できなければならない。
- **FR-012**: システムは、削除実行前にユーザーへ確認を求め、確認が得られるまで削除を
  実行してはならない。
- **FR-013**: システムは、存在しない目標IDに対する編集・削除操作にエラーを返し、
  他のデータに影響を与えてはならない。
- **FR-014**: システムは、習慣が削除された場合、その習慣に紐づく目標も併せて削除
  しなければならない。
- **FR-015**: システムは、同一習慣に対して期間が重複する複数の目標の設定を許可し、
  それぞれ独立して進捗を計算しなければならない。

### Key Entities

- **目標（Goal）**: 習慣（Habit）への参照、開始日、終了日、目標回数、作成日時、
  更新日時を持つ。
- **進捗（Progress）**: 永続化されるエンティティではなく、目標期間内のチェックイン数
  と目標回数から都度計算される導出値（進捗率・達成フラグ）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ユーザーは1回の操作で新しい目標を設定できる。
- **SC-002**: 目標設定・チェックイン操作後、3秒以内に進捗率が一覧に反映される。
- **SC-003**: 開始日が終了日より後、目標回数が0以下、対象習慣が存在しない、のいずれか
  の不正な入力は100%エラーとして検出される。
- **SC-004**: 進捗率は実績チェックイン数と目標回数の比率として100%の精度で計算され、
  目標回数以上の実績がある場合は100%・達成として表示される。
- **SC-005**: 目標の削除操作は100%確認ステップを経て実行され、確認なしの削除は
  発生しない。

## Assumptions

- 目標は単一の習慣に対して設定するものとし、複数習慣・カテゴリ単位の目標は本フェーズ
  のスコープ外とする。
- 期間はユーザーが任意に指定する開始日・終了日とし、「今月」等のプリセット期間の
  自動設定機能は本フェーズのスコープ外とする（ユーザーが手動で月初・月末を指定すれば
  同等のことができる）。
- 同一習慣に対して期間が重複する複数の目標の設定を許可する。
- 目標回数を超える実績があっても進捗率は100%として表示し、超過分の記録や表示は
  行わない。
- 達成した目標に対する自動アーカイブ・通知等の機能は本フェーズのスコープ外とする。
